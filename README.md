# ai-dev-workflow

> 让 AI 生成规范、不跑偏代码的完整开发流程 —— 规格驱动（SDD）+ 分层测试先行（TDD）+ 收敛验证

一套从**需求文档到上线**的 AI 辅助开发流程规范，配套**可复制的中间产物模板**和**可安装的 Agent Skill**。适用于 Java 服务端项目（Controller → Service → DAO/Mapper → 数据库；Quartz 定时任务；RabbitMQ 消息），方法论可推广到其他语言。

## 为什么需要这套流程

直接丢给 AI 一句提示词让它写代码，结果往往是：代码能跑但没人敢维护、接口悄悄偏离设计、测试从零开始、评审面对千行代码无从下手。

这套流程把 AI 编码约束进一条 5 步流水线，核心是四个字：**不跑偏**。

| 防跑偏手段 | 作用 |
|---|---|
| 类型化模板 | Controller/Listener/Job 各自方案格式固定，AI 没有"发挥空间" |
| 验收场景前置 | 方案阶段就写死"怎么算对"，直接翻译成测试 |
| 约束硬规则 | 项目约束写成"能检查对错"的规则，AI 逐条对照 |
| 角色分离 | 写测试的人/标准 ≠ 实现代码的 AI，防止"骗绿" |
| 收敛兜底 | 实现完按类型逐条核对，防规格漂移 |

## 流程一览

```
需求文档
  │
  ▼
① 需求分析 ──→ 功能清单总览（表格：功能项/类型/优先级/依赖/验收标准）
  │
  ▼
② 技术架构 ──→ 技术架构 + 项目约束（框架/中间件/版本，硬规则）
  │
  ▼
③ 技术方案 ──→ 每功能项一份技术方案 md（按类型套模板：Controller/Listener/Job）
  │              含验收场景（测试用例蓝本）
  ▼
④ 任务拆解 + 契约测试（人主导）──→ 任务拆解.md + 红色测试 + DDL
  │
  ▼
⑤ AI 编码 + 收敛验收（AI 主导）──→ 绿色代码 + 验收报告
  │
  ▼
人工验收 ──→ 上线
```

## 快速开始

### 方式一：纯手工使用模板（无需任何工具）

1. 从 `templates/` 复制需要的模板到你的项目 `docs/` 目录
2. 按 ①→⑤ 顺序填写（每份模板开头有填写说明）
3. 第 ⑤ 步把 `5.1-编码指令.md` 的内容连同 `任务拆解.md` 一起发给 AI

### 方式二：安装 Skill（Claude Code / Codex / OpenCode 等支持 skill 的 Agent）

#### 1. 安装

将 `skill/ai-dev-workflow/` 复制到你的 skills 目录：

```bash
# Claude Code
cp -r skill/ai-dev-workflow ~/.claude/skills/

# Codex / OpenCode
cp -r skill/ai-dev-workflow ~/.agents/skills/
```

> 注意：本项目自带 `.gitignore` 的 `!` 规则保证 `SKILL.md` 会被克隆下来；若你从别处拷贝，确保 `SKILL.md` 文件存在。

#### 2. 触发方式（对 Agent 说什么）

| 你想做什么 | 对 Agent 说 |
|---|---|
| 完整走一遍 5 步流程 | "按流程开发 XX 模块" / "从需求到代码，按流程来" |
| 只要第 1 步 | "先生成 XX 模块的功能清单" |
| 只要技术方案 | "给 XX 功能写技术方案" |
| 拆任务 | "按技术方案拆任务" / "生成任务拆解" |
| 写测试 | "按技术方案写契约测试" |
| AI 编码 | "按任务拆解实现，让测试变绿" |

#### 3. Skill 会做什么

安装后，Agent 按 `SKILL.md` 中的 5 步流程执行，每一步使用对应模板：

| 步骤 | 动作 | 使用的模板 |
|---|---|---|
| ① 需求分析 | 生成功能清单总览（表格） | `templates/01-功能清单.md` |
| ② 技术架构 | 生成技术架构 + 项目约束 | `templates/02-项目约束.md` |
| ③ 技术方案 | 按类型生成技术方案 | `templates/3.1/3.2/3.3-技术方案-*.md` |
| ④ 任务拆解 + 契约测试 | 生成任务清单 + 红色测试 | `templates/4.1-任务拆解.md`、`4.2-接口契约测试.md` |
| ⑤ AI 编码 + 收敛验收 | 让测试变绿 + 输出验收报告 | `templates/5.1-编码指令.md`、`5.2-验收报告.md` |

> `SKILL.md` 内的模板路径是相对 skill 目录的（`templates/xxx.md`），安装后请保持 `skill/ai-dev-workflow/` 目录结构与仓库一致，模板才能被正确引用。若你希望 Agent 引用仓库根目录的 `templates/`，可将 SKILL.md 中的 `templates/` 改为你的实际路径。

#### 4. 重要提示（防"骗绿"）

- **测试必须由你写**（或审核），不要交给实现代码的同一个 Agent——否则它会改弱断言来"骗绿"
- **第 ③ 步是质量闸门**：技术方案里有"待定/视情况"就继续追问，不要带歧义进入编码
- **项目约束要能检查对错**：写"统一用 MyBatis-Plus，禁止原生 JDBC"，不要写"尽量用规范的写法"

## 中间产物一览

| 步骤 | 产物 | 谁主导 |
|---|---|---|
| ① 需求分析 | 功能清单总览（表格） | 人 |
| ② 技术架构 | 技术架构 + 项目约束（硬规则） | 人 |
| ③ 技术方案 | 每功能项一份方案 md（类型化 + 验收场景） | 人 + AI 辅助 |
| ④ 任务拆解 + 契约测试 | 任务拆解.md + 红色测试 + DDL | 人 |
| ⑤ AI 编码 + 收敛验收 | 绿色代码 + 验收报告 | AI + 人验证 |
| 验收 | 可上线 | 人 |

## 适用场景

- ✅ 团队协作、生产上线、多 Controller 复杂模块
- ✅ 需要长期演进、多人维护的服务端项目
- ✅ 对代码规范、可测试性、可追溯性有要求的团队
- ⚠️ 原型验证、个人小工具、一次性脚本 → 这套流程偏重，直接用 Vibe Coding 即可
