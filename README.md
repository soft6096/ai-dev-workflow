# ai-dev-workflow

> 让 AI 生成规范、不跑偏代码的完整开发流程 —— 规格驱动（SDD）+ 分层测试先行（TDD）+ 收敛验证

一套从**需求文档到上线**的 AI 辅助开发流程规范，配套**可复制的中间产物模板**和**可安装的 Agent Skill**。适用于 Java 服务端项目（Controller → Service → DAO/Mapper → 数据库；Quartz 定时任务；RabbitMQ 消息），方法论可推广到其他语言。

## 为什么需要这套流程

直接丢给 AI 一句提示词让它写代码，结果往往是：代码能跑但没人敢维护、接口悄悄偏离设计、测试从零开始、评审面对千行代码无从下手。

这套流程把 AI 编码约束进一条 5 步流水线，核心是四个字：**不跑偏**。

| 防跑偏手段 | 作用 |
|---|---|
| 类型化模板 | Controller/Listener/Job 各自方案格式固定，AI 没有"发挥空间" |
| 验收场景前置 | 方案阶段就写死"怎么算对"，直接翻译成测试 |
| 约束硬规则 | 项目约束写成"能检查对错"的规则，AI 逐条对照 |
| 角色分离 | 写测试的人/标准 ≠ 实现代码的 AI，防止"骗绿" |
| 收敛兜底 | 实现完按类型逐条核对，防规格漂移 |

## 流程一览

```
需求文档
  │
  ▼
① 需求分析 ──→ 功能清单总览（表格：功能项/类型/优先级/依赖/验收标准）
  │
  ▼
② 技术架构 ──→ 技术架构 + 项目约束（框架/中间件/版本，硬规则）
  │
  ▼
③ 技术方案 ──→ 每功能项一份技术方案 md（按类型套模板：Controller/Listener/Job）
  │              含验收场景（测试用例蓝本）
  ▼
④ 任务拆解 + 契约测试（人主导）──→ 任务拆解.md + 红色测试 + DDL
  │
  ▼
⑤ AI 编码 + 收敛验收（AI 主导）──→ 绿色代码 + 验收报告
  │
  ▼
人工验收 ──→ 上线
```

## 快速开始

### 方式一：纯手工使用模板（无需任何工具）

1. 从 `templates/` 复制需要的模板到你的项目 `docs/` 目录
2. 按 ①→⑤ 顺序填写（每份模板开头有填写说明）
3. 第 ⑤ 步把 `5.1-编码指令.md` 的内容连同 `任务拆解.md` 一起发给 AI

### 方式二：安装 Skill（Claude Code / Codex 等支持 skill 的 Agent）

将 `skill/ai-dev-workflow/` 复制到你的 skills 目录：

```bash
# Claude Code
cp -r skill/ai-dev-workflow ~/.claude/skills/

# Codex / OpenCode
cp -r skill/ai-dev-workflow ~/.agents/skills/
```

安装后，对 Agent 说"**按流程开发 XX 模块**"即可自动走完 5 步。

## 中间产物一览

| 步骤 | 产物 | 谁主导 |
|---|---|---|
| ① 需求分析 | 功能清单总览（表格） | 人 |
| ② 技术架构 | 技术架构 + 项目约束（硬规则） | 人 |
| ③ 技术方案 | 每功能项一份方案 md（类型化 + 验收场景） | 人 + AI 辅助 |
| ④ 任务拆解 + 契约测试 | 任务拆解.md + 红色测试 + DDL | 人 |
| ⑤ AI 编码 + 收敛验收 | 绿色代码 + 验收报告 | AI + 人验证 |
| 验收 | 可上线 | 人 |

## 适用场景

- ✅ 团队协作、生产上线、多 Controller 复杂模块
- ✅ 需要长期演进、多人维护的服务端项目
- ✅ 对代码规范、可测试性、可追溯性有要求的团队
- ⚠️ 原型验证、个人小工具、一次性脚本 → 这套流程偏重，直接用 Vibe Coding 即可
