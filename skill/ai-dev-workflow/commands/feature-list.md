# 功能清单（需求分析）

根据输入的需求文档/需求描述，生成**功能清单总览文件**。

## 输入

- 需求文档（模块级）或用户直接给出的需求描述

## 执行

1. 将模块拆解为功能项，每项一行，填入表格：

| # | 功能项 | 类型 | 优先级 | 依赖 | 验收标准 |
|---|--------|------|--------|------|----------|
| 1 |  | Controller/Listener/Job | P1/P2/P3 | 依赖 #编号 或 — | 可验证的描述 |

2. 类型说明：
   - `Controller`：HTTP 接口功能
   - `Listener`：MQ 消费者（RabbitMQ）
   - `Job`：定时任务（Quartz）
   - 其他类型须注明触发方式

3. 验收标准必须**可验证**（"XX 可调通/可生效"），禁止写"实现 XX 功能"

4. **读取版本号并创建版本化目录**：从需求文档/PRD 中读取模块**版本号**（V 开头，如 V1.2.0；需求文档未标注版本号则向用户询问），生成目录名 `<模块名>V<版本号>-<YYYYMMDDHHMMSS>`（时间戳 = 生成时刻），并在该目录下创建 `1.1-功能清单.md`。后续所有产物（1.2/3.x/4.1/5.2）都落入该目录，目录名一旦创建不再变更。

## 输出

`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/1.1-功能清单.md`（参考模板 `templates/1.1-功能清单.md`，文件名带 1.1 编号，与流程步骤对应）

## 完成标准

- [ ] 每个功能项有类型标签 + 可验证验收标准 + 依赖标注
- [ ] 粒度可独立开发、独立测试、独立交付
- [ ] 通过 `/clarify` 完成歧义/边界/依赖澄清后，才可进入技术方案（`/design-*`）
