# 项目约束（技术架构）

根据功能清单，确定技术架构并生成**项目约束文件**。

## 输入

- 第①步的功能清单
- 用户的技术栈偏好（可选）
- 规范 skill：技术架构选型/依赖版本/多模块结构对照 **build-standards**（依赖版本管理、多模块拆分约束）
- **存量适配模式（可选）**：若已走 0.5 `/legacy-scan` 且用户选择跳过存量优化，读 `docs/0.5-存量代码扫描.md`——**约束来源 = 老项目实际约定，不是规范 skill**

## 执行

**先判定模式**：

| 模式 | 判定 | 约束来源 | 模板 |
|---|---|---|---|
| 标准模式 | 新项目 / 未走 0.5 | 规范 skill（build-standards 等） | `templates/2.1-项目约束.md` |
| 存量适配模式 | 已走 0.5 且用户选择跳过存量优化 | **老项目实际约定**（0.5 扫描结论） | `templates/2.1-项目约束-存量适配.md` |

1. **标准模式**（新项目 / 未走 0.5）——三步生成：
   a. 确定技术架构总览：

| 类别 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 开发框架 | | | |
| ORM | | | |
| 数据库 | | | |
| 缓存/消息/调度 | | | |

   b. 生成**硬性约束**（每条必须能检查对错，禁止"尽量/建议"）：

```markdown
1. 统一使用 XX，禁止 YY
2. 所有新增接口必须加 @RequiresPermissions 权限注解
3. 数据库操作统一走 Service 层
4. 涉及多表写入必须 @Transactional
5. 注释规范：全量注释 —— 所有类（DTO/VO/Config 等，仅示例非穷举）类注释写清职责、所有变量/字段注释写清含义、所有方法（含测试方法）注释（@param/@return 写业务含义）、方法体 ≥2 个逻辑步骤编号步骤注释、复杂逻辑 // WHY:（详见模板"注释规范"章节）
...
```

   c. 生成**公共组件规范**（防重复代码，模板"公共组件规范"章节默认含，可增删）：

```markdown
- 包结构约定：无状态工具类 → common/util/；可继承抽象基类/模板方法 → common/base/
- 同一逻辑出现第 2 个使用点 → 必须抽公共组件，禁止复制粘贴
- 编码前先扫描 common/ 目录，已有组件必须复用
- 任务拆解"公共组件" Phase 列出的组件必须实现并被使用点复用
...
```

2. **存量适配模式**（已走 0.5 且用户选择跳过存量优化）——按模板 `templates/2.1-项目约束-存量适配.md` 生成：

- 从 `docs/0.5-存量代码扫描.md` 提取约束，**约束来源 = 老项目实际约定**：
  - 包结构：新代码放入哪个包（与老项目分层一致）
  - 返回体/公共组件：`R`/`Response`/分页类/异常处理类的类名与位置，对齐老项目，禁止自创
  - 命名风格：Java 命名 + 数据库字段命名与老项目一致
  - 中间件：数据库 / MQ / Redis / JOB 的**版本、账号、接入规范**与老代码一致（老项目怎么用，新代码就怎么用）
  - 复用老项目已有工具类/基类，禁止新写同名同类组件
- 每条约束标注老代码出处（类名/配置项/目录路径）
- 规范 skill 仅在老项目无对应约定时兜底

## 输出

- 标准模式：`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/2.1-项目约束.md`（参考模板 `templates/2.1-项目约束.md`，与 1.1/1.2 等产物同目录）——**生成后同步写入项目根 `AGENTS.md`**（不存在则创建，或追加到已有规范章节），成为整个项目的长期规范
- 存量适配模式：`docs/<模块名>V<版本号>-<YYYYMMDDHHMMSS>/2.1-项目约束.md`（参考模板 `templates/2.1-项目约束-存量适配.md`；包结构/返回体/命名/中间件对齐老项目，每条约束标注老代码出处）——**仅本次开发流程生效，不写入项目 AGENTS.md**（老项目未接入规范体系，本次约束只约束本次新代码）

## 完成标准

- [ ] 模式判定正确（存量适配模式必须有 0.5 扫描结论支撑）
- [ ] 每条约束是"能检查对错"的规则
- [ ] 版本号已写死
- [ ] 覆盖：编码规范/事务/权限/日志/幂等/防重入/注释规范/公共组件
- [ ] 存量适配模式：包结构/返回体/字段命名/中间件（数据库/MQ/Redis/JOB 等版本、账号、接入规范）与老项目一致，每条有老代码出处
- [ ] 标准模式：约束已同步写入项目根 AGENTS.md（长期规范）；存量适配模式：确认不写入 AGENTS.md
