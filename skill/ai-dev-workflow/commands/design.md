# 技术方案（Design）

为功能清单中的某个功能项生成技术方案。**按功能项类型自动路由到对应模板**，无需手动指定。

## 输入

- 功能清单（`docs/<模块名>/1.1-功能清单.md`）—— **类型路由的依据**
- 项目约束（`docs/2.1-项目约束.md`）

## 类型路由（核心逻辑）

1. 在功能清单中查找目标功能项（按名称或编号）
2. 读取该功能项的**类型列**，路由到对应模板：

| 功能清单类型列 | 使用模板 | 方案核心内容 |
|---|---|---|
| `Controller` | `templates/3.1-技术方案-Controller.md` | 接口清单/入参出参 JSON/校验规则/DDL/权限事务/验收场景 |
| `Listener` | `templates/3.2-技术方案-Listener.md` | 监听配置/消息体/消费逻辑/幂等/死信/验收场景 |
| `Job` | `templates/3.3-技术方案-Job.md` | 调度配置/执行逻辑/防重入/批处理/验收场景 |

3. 若功能清单中找不到该功能项或类型列缺失 → 停下来询问用户，不要自行猜测类型

## 通用要求（所有类型通用）

- 基本信息：功能项编号、优先级、依赖
- **验收场景**：合法 + 非法 + 边界（测试用例蓝本，供第 4 步翻译成测试）
- **注释要求**：类/接口 Javadoc 说明
- **架构自检（公共组件识别）**：见下方独立小节，结果写入技术方案"公共组件识别"章节
- 横切关注点对照项目约束逐条检查
- 完成标准自检（对应模板末尾）

## 架构自检（公共组件识别，每功能项必做）

防重复代码的关口设在**方案期**，不靠编码期"顺手"（编码约束禁止设计外抽取）：

1. 逐条列出本方案中重复出现的逻辑片段（≥2 处使用点：校验、转换、状态流转、幂等、锁、分页等）
2. 判定抽取类型：
   - 无状态纯逻辑 → 工具类（`common/util/`）
   - 有状态/模板方法/共享生命周期 → 抽象基类（`common/base/`）
3. 写出设计：方法签名 / 继承关系 / 归属包
4. 结果写入技术方案"公共组件识别"章节；无重复逻辑则写"无"，4.1 拆任务时 Phase 0.5 留空

## 输出

`docs/<模块名>/3.x-<功能名>-技术方案.md`（每功能项一份，文件名带 3.x 编号，x 按功能项序号递增）

## 完成标准（质量闸门）

- [ ] 类型路由正确（读功能清单类型列，非自行猜测）
- [ ] 入参/出参/错误码/校验规则无"待定/视情况"
- [ ] 数据模型 DDL 完整（字段/类型/索引/约束）
- [ ] 验收场景含合法 + 非法 + 边界
- [ ] 类型特有横切关注点已写明（Controller→权限事务 / Listener→幂等死信 / Job→防重入批处理）
- [ ] 架构自检完成：公共组件已识别并给出签名/包路径（无重复则已注明"无"）
- [ ] 有注释要求
