# 技术方案（Design）

为功能清单中的某个功能项生成技术方案。**按类型列选模板组合**（3.0 通用骨架 + 类型模板），无需手动指定。

## 输入

- 功能清单（`docs/<模块名>/1.1-功能清单.md`）—— **类型路由的依据**
- 项目约束（`docs/2.1-项目约束.md`）

## 模板选择（核心逻辑）

1. 在功能清单中查找目标功能项（按名称或编号）
2. 读取该功能项的**类型列**，选模板组合（3.0 通用骨架 + 类型模板配套）：

| 功能清单类型列 | 使用模板组合 | 四段差异（一句话） |
|---|---|---|
| `Controller` | `3.0-技术方案-通用骨架.md` + `3.1-技术方案-Controller.md` | 接口清单 / JSON+校验 / 转发编排 / 权限事务 |
| `Listener` | `3.0-技术方案-通用骨架.md` + `3.2-技术方案-Listener.md` | 监听配置 / 消息体 / 消费流程 / 幂等死信 |
| `Job` | `3.0-技术方案-通用骨架.md` + `3.3-技术方案-Job.md` | 调度配置 / 无入参 / 执行流程 / 防重入批处理 |
| 无入口 | 仅 `3.0-技术方案-通用骨架.md` | 配置/工具/纯数据，跳过类型段 |

3. 生成方式：3.0 骨架通用章节（基本信息/验收场景/公共组件识别/注释要求/自检）必填；类型特有内容按 3.x 模板四段（入口定义/数据契约/核心逻辑/关注点）填充，合并为**一份完整方案**
4. 若功能清单中找不到该功能项或类型列缺失 → 停下来询问用户，不要自行猜测类型

## 通用要求（所有类型通用）

- 基本信息：功能项编号、优先级、依赖
- **验收场景**：合法 + 非法 + 边界（测试用例蓝本，供第 4 步翻译成测试）
- **注释要求**：类/接口 Javadoc 说明
- **架构自检（公共组件识别）**：见下方独立小节，结果写入方案"公共组件识别"章节
- 横切关注点对照项目约束逐条检查
- 完成标准自检（3.0 通用部分 + 类型模板特有部分）

## 架构自检（公共组件识别，每功能项必做）

防重复代码的关口设在**方案期**，不靠编码期"顺手"（编码约束禁止设计外抽取）：

1. 逐条列出本方案中重复出现的逻辑片段（≥2 处使用点：校验、转换、状态流转、幂等、锁、分页等）
2. 判定抽取类型：
   - 无状态纯逻辑 → 工具类（`common/util/`）
   - 有状态/模板方法/共享生命周期 → 抽象基类（`common/base/`）
3. 写出设计：方法签名 / 继承关系 / 归属包
4. 结果写入技术方案"公共组件识别"章节；无重复逻辑则写"无"，4.1 拆任务时 Phase 0.5 留空

## 输出

`docs/<模块名>/3.x-<功能名>-技术方案.md`（每功能项一份，文件名带 3.x 编号，x 按功能项序号递增）

## 完成标准（质量闸门）

- [ ] 模板组合选择正确（读功能清单类型列；无入口形态已走"仅 3.0"路径）
- [ ] 通用章节完整：验收场景含合法 + 非法 + 边界，公共组件识别完成，注释要求已写明
- [ ] 类型特有内容按四段（入口定义/数据契约/核心逻辑/关注点）取自对应 3.x 模板
- [ ] 入参/出参/错误码/校验规则无"待定/视情况"
- [ ] 数据模型 DDL 完整（字段/类型/索引/约束）
- [ ] 类型特有横切关注点已写明（Controller→权限事务 / Listener→幂等死信 / Job→防重入批处理）
