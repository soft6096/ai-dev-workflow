# 技术方案：Listener 类型模板（异步 MQ）

> 使用说明：这是第 ③ 步技术方案的**类型模板**（Listener，MQ 消费者）。
> 与 `3.0-技术方案-通用骨架.md` 配套使用：**方案 = 3.0 通用骨架 + 本模板四段内容**。
> 幂等和失败处理是 Listener 的**生死线**——重复消息、失败重试、死信队列必须在方案里写死。
> 本文件只含类型特有内容，不含通用章节。

## 四段式内容（并入 3.0 骨架，本类型必填）

### 一、入口定义 → 监听配置

- 交换机/队列：exchange=order.exchange, queue=order.status.queue
- 路由键：order.status.changed
- 交换机类型：topic（fanout 则无需路由键）
- ACK 方式：手动（防丢消息）

### 二、数据契约 → 消息体结构 + 字段约束

```json
{
  "orderId": 10001,
  "status": "PAID",
  "amount": 299.00,
  "userId": 88,
  "timestamp": "2026-08-07T10:00:00+08:00"
}
```

- orderId：必填 Long，订单号
- status：必填，枚举 PAID/CLOSED/SHIPPED/COMPLETED
- timestamp：可选，事件发生时间（用于乱序判断）

### 三、核心逻辑 → 消费主流程

1. 反序列化消息，校验必填字段（orderId/status），非法则丢弃并告警
2. 幂等检查：查 order_status_log 唯一键（order_id + status），存在则直接 ACK 返回
3. 查询订单当前状态，比较事件时间戳：旧时间戳消息忽略（乱序）
4. 更新 sys_order.status + 写入 order_status_log
5. 手动 ACK

- **复杂业务**（多表写/状态流转/算法/并发）→ 必写"业务规则"小节（同 3.1 要求）：状态流转 / 计算规则 / 并发处理
- **跨功能项规则**（如状态机横跨多入口）→ 按 3.0 归属规则：引用最先触碰的功能项编号，只写本入口触发的迁移

### 四、关注点 → 幂等与失败处理

- **幂等**：唯一键 order_id + status（order_status_log 建联合唯一索引），重复消息直接跳过；捕获 DuplicateKeyException 视为成功
- **失败处理**：消费异常重试 3 次（指数退避 1s/2s/4s），仍失败进死信队列（order.status.dead.queue）+ 告警
- **反序列化失败**：不重试，直接丢弃 + 告警日志
- **订单不存在**：不处理，ACK + 告警（避免死信堆积）

  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id    BIGINT NOT NULL COMMENT '订单ID',

  create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
