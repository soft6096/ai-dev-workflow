# 项目约束 - <模块名>

> 使用说明：这是第 ② 步"技术架构"的产物模板。约束是整个流程的"宪法"——第 ③ 步技术方案、第 ⑤ 步 AI 编码都必须逐条对照。
> **两种模式**：
> - **标准模式（本模板）**：新项目 / 未走 0.5 存量扫描——按规范 skill 生成约束，模板如下。**生成后同步写入项目根 `AGENTS.md`**（不存在则创建，或追加到已有规范章节），成为整个项目的长期规范（后续所有模块开发都遵守，不限于本次）。
> - **存量适配模式**：老代码迭代新需求、已走 0.5 且用户选择跳过存量优化——按 `0.5-存量代码扫描.md` 的老项目约定生成约束（包结构/返回体/命名/中间件对齐老代码），模板见 `2.1-项目约束-存量适配.md`，**不要用本模板**；该模式仅本次开发流程生效，不写入 AGENTS.md。
> 填写要点：
> - 每条约束必须**能检查对错**（是/否可判定），禁止"尽量""建议""最好"等软约束
> - 版本号写死：Spring Boot 3.2.x 而不是"新版本"
> - AI 编码时逐条对照，违反即为不合格
> 下方为**示例项目**（RuoYi-Vue 系）的完整约束，复制后替换成你的技术栈。

## 硬性约束（AI 编码时必须遵守）

| # | 约束 | 违反判定 |
| :---: | :--- | :--- |
| 1 | 统一使用 MyBatis-Plus，禁止原生 JDBC | 出现原生 JdbcTemplate/JDBC 代码 |
| 2 | 所有新增接口必须加 @RequiresPermissions 权限注解，权限码格式 `模块:资源:操作` | 接口无权限注解或格式不符 |
| 3 | 数据库操作统一走 Service 层，Controller 禁止直接调用 Mapper | Controller 注入 Mapper |
| 4 | 涉及多表写入的方法必须 @Transactional，事务只放在 Service 层 | 多表写无事务 / Controller 加事务 |
| 5 | 返回体统一使用 `Response<T>`（code/message/data），禁止直接返回 Map；分页用 PageResult | 返回 R/Map/其他包装 |
| 6 | 实体类字段命名统一驼峰，表字段统一下划线；表名小写+下划线+**统一业务前缀**（规则见 database-standards `table-design-standards`） | 命名不规范 |
| 7 | 禁止 System.out.println，统一使用 lombok @Slf4j 的 log | 出现 System.out |
| 8 | Listener 消费必须做幂等处理（唯一键或状态位），且手动 ACK | 无幂等 / 自动 ACK |
| 9 | Job 必须防重入（Redis 分布式锁或状态位），批处理单次不超过 500 条 | 无锁 / 批量超限 |
| 10 | 所有时间字段用 DATETIME，禁止字符串存时间 | 时间用 VARCHAR |
| 11 | 金额字段用 DECIMAL(10,2)，禁止 float/double | 金额用浮点 |
| 12 | 逻辑删除统一 del_flag（0存在 2删除），禁止物理删除业务数据 | 物理 DELETE |
| 13 | 业务异常统一抛 `BusinessException(ErrorCode, message)`，错误码集中定义，由全局异常处理器转换；禁止 try-catch 后吞掉（见 java-code-standards 异常规范） | 空 catch / 吞异常 / 裸 RuntimeException |

> [!WARNING] 硬性约束是验收红线
> 每条约束都能判定对错（见"违反判定"列），AI 编码时逐条对照，违反即为不合格。
