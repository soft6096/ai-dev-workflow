# Tasks: 订单管理（US-001）

> 使用说明：这是第 ④ 步"任务拆解"的产物模板。根据技术方案 md 拆成可独立实现、独立测试的任务清单。
> 格式：`[ID] [P?] [Phase] 描述（文件路径 + 验收方法）`
> - `[P]` = 可并行（不同文件、无依赖）
> - Phase 顺序固定：先数据层 → 再业务 → 再接口/消费/调度
> - 契约测试（Phase 1）必须先写并确认**红**——它是 AI 编码的标尺
> - 按类型选一套模板，删掉不适用的
> 下方为**完整示例**（订单创建，Controller 类型），带占位符的骨架模板见各 Phase 注释。

---

## Controller 类型模板（示例：订单创建）

### Phase 0 数据库（共享基础设施）

- [ ] T001 建表 SQL（按技术方案 DDL，含索引/约束）
      - 文件：`docs/sql/order.sql`（sys_order + order_item + order_status_log）
      - 验收：在 MySQL 执行 DDL 成功，`SHOW CREATE TABLE sys_order` 与方案一致
- [ ] T002 实体类 + Mapper 接口 + XML
      - 文件：`src/main/java/com/example/order/domain/Order.java`、`OrderMapper.java`
      - 验收：`mvn compile` 通过

### Phase 1 契约测试（★ 最先写，先红）

- [ ] T003 按技术方案验收场景写订单创建接口测试
      - 文件：`src/test/java/com/example/order/controller/OrderControllerTest.java`
      - 验收：运行测试**全红**（接口未实现，404/编译失败）

### Phase 2 Service 层

- [ ] T004 创建订单核心逻辑 + 单元测试（金额计算、库存扣减、状态流转）
      - 文件：`OrderServiceImpl.java` + `OrderServiceImplTest.java`
      - 验收：单元测试绿，金额计算正确（含折扣/运费）
- [ ] T005 纯转发方法（列表查询）——跳过测试

### Phase 3 Controller 层

- [ ] T006 订单接口实现 + 集成测试（入参→校验→Service→DB 走通）
      - 文件：`OrderController.java`
      - 验收：T003 契约测试变绿，`POST /order` 真实验证（H2 或测试库）

### Phase 4 验证

- [ ] T007 quickstart：启动应用，curl 调通主流程
      - 验收：`curl -X POST /order -d '{}'` 返回 200 + 订单号

### Phase 5 收尾

- [ ] T008 注释、事务、权限注解（对照项目约束 #2/#4）
      - 验收：接口有 Javadoc，POST 有 @RequiresPermissions("order:order:add")，创建含 @Transactional

## 通用占位符骨架（复制用）

```
【功能名】任务拆解.md
├── Phase 0  数据库
│   ├── T001  建表 SQL（按技术方案 DDL）→ 确认可执行
│   └── T002  实体类 + Mapper 接口 + XML → 编译通过
├── Phase 1  契约测试（★ 最先写，先红）
│   └── T003  按验收场景写测试（文件路径）
├── Phase 2  Service 层
│   ├── T004  核心业务逻辑 + 单元测试（文件路径）
│   └── T005  纯转发方法（跳过测试）
├── Phase 3  Controller 层
│   └── T006  接口实现 + 集成测试（文件路径）
├── Phase 4  验证
│   └── T007  quickstart：启动应用调通主流程
└── Phase 5  收尾
    └── T008  注释、事务、权限注解核对
```
