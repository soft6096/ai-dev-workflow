# 技术方案：订单状态同步（US-002）

> 使用说明：这是第 ③ 步"技术方案"的产物模板（Listener 类型，MQ 消费者）。
> 幂等和失败处理是 Listener 的**生死线**——重复消息、失败重试、死信队列必须在方案里写死。
> 下方内容为**完整示例**（订单状态同步），复制后替换成你的业务数据。

## 基本信息

- 功能项：#5 | 类型：Listener | 优先级：P1 | 依赖：#1

## 监听配置

- 交换机/队列：exchange=order.exchange, queue=order.status.queue
- 路由键：order.status.changed
- 消费组：order-service
- 交换机类型：topic（若用 fanout 则无需路由键）

## 消息体结构（入参 JSON 示例）

```json
{
  "orderId": 10001,
  "status": "PAID",
  "amount": 299.00,
  "userId": 88,
  "timestamp": "2026-08-07T10:00:00+08:00"
}
```

- orderId：必填 Long，订单号
- status：必填，枚举 PAID（已支付）/ CLOSED（已关闭）/ SHIPPED（已发货）/ COMPLETED（已完成）
- amount：可选 BigDecimal，订单金额
- userId：可选 Long
- timestamp：可选，事件发生时间（用于乱序判断）

## 出参/落库结果（处理后数据变化）

```json
// 更新 sys_order 表该订单的 status 字段
{
  "orderId": 10001,
  "oldStatus": "PENDING",
  "newStatus": "PAID",
  "updateTime": "2026-08-07T10:00:01+08:00"
}
```

## 消费逻辑（主流程）

1. 反序列化消息，校验必填字段（orderId/status），非法则丢弃并告警
2. 幂等检查：查 `order_status_log` 唯一键（order_id + status），存在则直接 ACK 返回
3. 查询订单当前状态，比较事件时间戳：若消息时间戳 < 当前状态变更时间，忽略（乱序）
4. 更新 sys_order.status
5. 写入 order_status_log（order_id, status, create_time）
6. 手动 ACK

## 幂等与失败处理

- 幂等方案：唯一键 order_id + status（order_status_log 建联合唯一索引），重复消息直接跳过
- 失败处理：消费异常重试 3 次（指数退避 1s/2s/4s），仍失败进死信队列（order.status.dead.queue）+ 告警
- 反序列化失败：不重试，直接丢弃 + 告警日志

## 涉及 Service 和表

- OrderService.updateStatus(orderId, newStatus, eventTime)
- 表：sys_order（status 字段）、order_status_log（幂等唯一键，DDL 见下）

```sql
-- 订单状态变更日志表（幂等唯一键）
CREATE TABLE order_status_log (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id    BIGINT NOT NULL COMMENT '订单ID',
  status      VARCHAR(20) NOT NULL COMMENT '状态',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  UNIQUE KEY uk_order_status (order_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单状态变更日志';
```

## 边界场景

- 重复消息 → 幂等跳过（唯一键冲突，捕获 DuplicateKeyException 后视为成功）
- 乱序消息（SHIPPED 先于 PAID 到达）→ 按时间戳忽略旧状态
- 消息体缺失字段 → 丢弃 + 日志告警
- 订单不存在 → 不处理，ACK + 告警（避免死信堆积）

## 验收场景

| # | 场景 | 期望 |
|---|------|------|
| 1 | 正常消息 | sys_order.status 更新 + order_status_log 写入 |
| 2 | 同一条消息发两次 | 第二次幂等跳过，状态不重复变更，日志只有一行 |
| 3 | 非法消息体 | 丢弃 + 告警日志，不入死信 |
| 4 | 消费失败 3 次 | 进死信队列 order.status.dead.queue |
| 5 | 乱序消息 | 旧时间戳消息被忽略 |
